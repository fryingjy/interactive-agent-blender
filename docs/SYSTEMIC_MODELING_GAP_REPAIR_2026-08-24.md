# Systemic modeling-gap repair — 2026-08-24

## Outcome

The audit confirmed that poor prop results were not primarily caused by missing Blender commands.
They were caused by weak evidence identity, unbound verifier replay, downstream patching of upstream
failures, unlimited local repair, and runtime paths that could mutate assets without proving that a
reference-analysis gate had authorized the same target.

This pass repairs those system defects. It does **not** claim professional modeling autonomy. The
next valid proof remains a new unfamiliar asset completed through the stricter loop and accepted on
visible likeness, topology, editability, and production readiness.

## Defects and repairs

| Defect | Consequence | Repair |
| --- | --- | --- |
| Semantic review was not bound to the exact target, render, and authorized reference artifacts | A valid old review could be replayed against changed geometry | Critic schema v2 validates target ID, request fingerprint, local artifact hashes, candidate view/hash map, reference hashes, component IDs, and current prompt/provider |
| Critic reported symptoms but not the earliest failed reasoning stage | Representation failures could be disguised as proportion or surface work | Every mismatch now carries root cause and repair scope; upstream failures explicitly prohibit bevel, crease, SubD, shading, material, and detail patches |
| Reference audits accepted URL provenance without a fixed local artifact | A changing or substituted image could authorize geometry | Materialized references now require verified SHA-256; audits publish the authorized hash set; modeling specs may cite only a subset of that set |
| Reference-analysis subrecords could each pass while naming different targets | Cross-target evidence bundles could authorize construction | Stage gate now checks target and variant consistency across reference audit, visual reconstruction, and modeling spec |
| Construction intent was implicit | Generic primitive assemblies could satisfy technical checks without preserving identity | A reference modeling spec now records semantic components, continuity, representation, justification, identity features, measurements, reversible depth policy, and pass criteria without imposing object-count quotas |
| Visual repairs had no effective global limit | The system could spend many edits polishing one wrong representation | Repair is capped at three attempts per stage/region; two stagnant measured attempts force a strategy change |
| Checkpoints did not retain exact visual focus | Multiple simultaneous edits made improvement attribution unreliable | Visual stage checkpoints bind artifacts and scene revision, preserve one dominant correction focus, carry previous focus, and disallow parallel repairs |
| Command-sequence gating recognized mainly tutorial construction | Held-out/reference builds and correction-only sequences could bypass pre-modeling evidence | The runner now gates every real-asset mutation, distinguishes tutorial/reference/lab paths, requires exact blockout review before surface work, and checks target identity across records |
| Live typed runtime could create or adopt geometry without evidence | Tool discipline depended on caller behavior | The live server now requires session-scoped reference authorization, hash-tags created objects, requires explicit binding for loaded objects, blocks strict global undo/restore, and binds transaction-created derivatives |
| Semantic-region metadata remained writable on unbound objects | Asset state could drift outside the authorization boundary | Region creation/update/deletion now requires the same target binding as geometry decisions |

## External architecture lessons adopted

- `image2blender` contributed the useful ideas of a pre-build identity/detail inventory, locked
  passes, and bounded repair. Its primitive-count and one-component-per-object assumptions were not
  adopted because this project deliberately supports connected Edit Mode/SubD cages.
- `blender-ai-mcp` reinforced goal-scoped references, readiness state, checkpoints, and retained
  correction focus.
- SEIG/“Thinking in Blender” supports staged generator/verifier inverse graphics rather than one
  long unverified build.
- EZBlender supports planning followed by tool-grounded reactive correction.
- LL3M supports editable Blender programs plus visual self-critique rather than an opaque final mesh.

## Remaining proof, in order

1. Select one bounded unfamiliar manufactured or fictional prop with usable multi-view evidence.
2. Produce and validate the reference modeling spec before Blender construction.
3. Build only a reversible sparse cage under strict runtime authorization.
4. Use fixed-view deterministic measurements and the semantic critic at each stage checkpoint.
5. Rebuild on upstream failure; never disguise it with surface polish.
6. Stop or change representation at the bounded repair limit.
7. Obtain post-model human review; only then continue to UV/material/export.
8. Repeat on unrelated geometry before promoting capability.
